# Content pipeline

Every asset and every piece of content in this game is generated by a script in `tools/`.
Those scripts are the source of truth; the files they produce are committed so the project
opens and runs without running anything first.

Only dependency: `pip install pillow`.

---

## The generators

| Script | Produces | Output |
|---|---|---|
| `gen_characters.py` | Character sprite sheets, `SpriteFrames`, portraits | `assets/art/characters/`, `assets/art/ui/portraits/` |
| `gen_world.py` | Props, weapons, tiles, buildings, backgrounds, FX, UI, item icons | `assets/art/` |
| `gen_emission.py` | Glow masks and light textures, derived from the art | `assets/art/emission/`, `assets/art/light/` |
| `gen_pwa_icons.py` | Installable app icons at 144, 180 and 512 px | `assets/pwa/` |
| `gen_audio.py` | Music, sound effects, ambience | `assets/audio/` |
| `gen_data.py` | Moves, enemies, food, books, items, weapons, shops, quests, dialogue, encounters, area metadata | `data/**/*.tres` |
| `gen_areas.py` | Area layouts | `data/areas/*.json` |
| `gen_scenes.py` | Godot scene files | `*.tscn` throughout the project |

Run them from the project root. Order only matters the first time: characters and world art
before data (which references textures), and data before areas.

```bash
python tools/gen_characters.py
python tools/gen_world.py
python tools/gen_emission.py   # after gen_world: it reads the art gen_world just wrote
python tools/gen_audio.py
python tools/gen_data.py
python tools/gen_areas.py
python tools/gen_scenes.py
```

## Characters

`gen_characters.py` builds a small skeletal rig and poses it. A character is a colour and
shape spec:

```python
"kip": spec(skin=(234, 190, 150), hair=(40, 28, 40), hair_style="spiky",
            shirt=(214, 58, 68), shirt_style="jacket", pants=(52, 70, 140),
            shoes=(246, 246, 246)),
```

The rig has a head, torso, two arms and two legs, each with three joints. Poses set joint
positions; the renderer draws each limb twice, once as a dark outline and once filled, with
a lighter top edge for form.

Animations are lists of poses with a frame rate and a loop flag. There are 29 of them:
idle, walk, run, three punches, kick, heavy, uppercut, spin kick, jump, jump kick, running
attack, dash, hurt, fall, lying, get-up, grab, grabbed, throw, grabbed punch, special,
ground stomp, pickup, weapon idle, weapon swing, item throw, victory, talk, block, taunt.

Each character is packed into one sheet with a matching `.tres` `SpriteFrames`, so the
engine gets a ready-to-use resource. The current set is 24 characters and 1,279 frames.

**To add a character:** add an entry to `CHARACTERS`, pick which animation set it needs
(`FULL_SET`, `ENEMY_SET` or `NPC_SET`), and re-run. Portraits are generated automatically
and the dialogue box picks them up by id.

## World art

`gen_world.py` draws everything else procedurally:

- **31 props**: trash cans, hydrants, cones, vending machines, benches, street lights,
  dumpsters, crates, barrels, tires, sewer grates, phone booths, signs, graffiti, puddles,
  bollards, bin bags, flyers, lockers, pallets, pipe stacks, AC units, fences, three cars,
  three awnings.
- **11 weapons**, drawn to read at a glance in a fist.
- **13 tiles** packed into one atlas: sidewalk, asphalt, curb, brick, concrete, metal,
  checkered floor, dirt, wood.
- **11 building facades** with windows lit at random, storefronts and abstract signage.
- **Backgrounds**: five sky gradients, three parallax skylines, a river band, two interior
  walls.
- **FX**: four spark variants, dust, impact rings, shadows, stars, sweat, alert bubbles.
- **UI**: panels, bars, six touch buttons, the joystick, icons and item art.

Most props end with `outline_alpha()`, which adds a one-pixel dark outline around every
opaque cluster. That single pass is most of what makes the art read as a coherent set.

## Audio

`gen_audio.py` synthesises everything with the Python standard library, so all audio is
original and freely distributable.

- **42 sound effects** built from oscillators (sine, square, 25% pulse, saw, triangle),
  filtered noise bursts and exponential envelopes. A heavy punch is a low sine sweeping
  down, a filtered noise burst and a sub layer, mixed and soft-clipped.
- **8 music tracks** written as note patterns on a 16th-note grid with bass, lead, harmony
  and drums: title, street, market, alley, industrial, boss, victory, shop.
- **5 ambience beds**: city, alley, interior, industrial, river.

Music is written as note names, which keeps the source readable:

```python
bass = ["D2", ".", "D2", ".", "-", "-", "A2", ".", ...]
lead = ["D4", ".", "F4", ".", "G4", ".", "A4", ".", ...]
drums = {"k": [0, 7, 8], "s": [4, 12], "h": [2, 6, 10, 14]}
```

Output is 16-bit mono WAV at 22.05 kHz. Godot compresses it on import; the whole soundtrack
and every effect fit inside the 2.8 MB export package alongside the art.

## Game data

`gen_data.py` holds all balance and writing, and emits typed Godot resources.

```python
move("uppercut", "Rising Uppercut", "uppercut",
     damage=19, input=IN_HEAVY, startup=6, active=5, recovery=20,
     launch_force=250.0, knockdown=True, energy_cost=10.0,
     learnable=True, price=200, required_level=2,
     description="Launches them straight up. Great for ending a light chain.")
```

Editing balance means editing one Python file where every value sits next to every other,
rather than opening 39 resource files in the inspector. The generated `.tres` files are
still normal Godot resources, editable by hand if you prefer.

Current content: 43 moves, 16 enemies, 16 foods, 8 books, 5 items, 11 weapons, 8 shops,
11 quests, 45 dialogues, 17 encounters, 8 areas.

## Areas

`gen_areas.py` writes a JSON layout per area. `Area.gd` reads it at runtime and builds the
street, so **there is no per-area scene or script**.

A layout describes:

```json
{
  "parallax": [ { "texture": "...", "scroll": 0.25, "y": -110 } ],
  "ground":   [ { "tile": "sidewalk_a", "y": 18, "height": 7 } ],
  "scenery":  [ { "texture": "...", "x": 210, "y": -194 } ],
  "props":    [ { "id": "trashcan", "x": 330, "breakable": true, "money": 12 } ],
  "weapons":  [ { "id": "bat", "x": 900 } ],
  "npcs":     [ { "id": "dez", "character": "dez", "x": 150, "dialogue": "intro_ferry" } ],
  "doors":    [ { "id": "to_market", "to": "lantern_market", "auto": true } ],
  "spawns":   [ { "id": "start", "x": 90, "y": 56 } ],
  "encounters": [ { "id": "ferry_pair", "x": 760, "width": 60 } ]
}
```

The vertical bands of a street are fixed and documented at the top of the generator:

```
ROAD_TOP  -46  road, parked cars, the back of the scene
BUILD_BASE  2  buildings stand here
SIDEWALK   18  sidewalk tiles begin
LANE_MIN   34  back of the walkable lane
LANE_MAX   74  front of the walkable lane
          130  sidewalk tiles end
CAMERA_Y  -12  camera centre
```

Because y doubles as lane depth and drives Y-sorting, keeping to these bands is what makes
characters, props and buildings layer correctly.

## Scenes

`gen_scenes.py` writes the `.tscn` files. Generating them keeps collision layers, node
paths and script bindings consistent across the player, both enemy scenes, weapons,
pickups, props, NPCs, doors and every UI layer.

If you edit a scene in the editor, either fold the change back into the generator or stop
running it for that file. The generator overwrites.

## Adding a new neighbourhood

The whole point of the pipeline. To add an area:

1. **Enemies** (optional): new entries in `ENEMIES` in `gen_data.py`. Reuse an existing
   character sprite or add one to `gen_characters.py`.
2. **Encounters**: entries in `ENCOUNTERS` naming those enemies and wave sizes.
3. **Dialogue**: entries in `DIALOGUES` for any new NPCs.
4. **Shops / quests** (optional): entries in `SHOPS` and `QUESTS`.
5. **Area metadata**: an entry in `AREAS` with a display name, music, ambience and map
   position.
6. **Layout**: a new block in `gen_areas.py` describing the street, plus doors in the
   neighbouring areas pointing at it.
7. Run `gen_data.py` and `gen_areas.py`.
8. Run the smoke test. It verifies that every id referenced by the new content resolves.

No engine code changes, no new scenes, no new scripts.

---

## Verification

The smoke test cross-checks the whole content set on every run:

- every move id in a `followups` list exists
- every move an enemy references exists
- every enemy an encounter spawns exists
- every item a shop sells exists
- every dialogue an NPC references exists
- every area a door leads to exists
- every prop's contents and every placed weapon exist
- every area has a layout file, and it parses

A typo in a content file fails the test rather than surfacing as a missing enemy hours
later.
